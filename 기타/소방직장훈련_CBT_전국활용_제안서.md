## 2. 추진 배경

소방공무원 직장훈련 성적평정은 **전술훈련평가**와 **이론평가(직장교육평가)** 두 축으로 구성된다. 전술훈련평가는 화재진압·구조·구급 등 소방활동에 필요한 팀별·개인별 전술 및 기술 능력을 소방관서 내 평가위원회가 직접 현장에서 평가하며, 이론평가는 직장 내 교육 및 필기시험 등을 통해 지식 수준을 평가한다. 두 항목은 각 2점 만점(총 4점)으로 구성되며, 소방청 지침에 따라 **연 2회(상반기·하반기)** 실시해야 한다.

전술훈련평가는 각 소방관서가 자체 평가위원회를 구성하여 운영하므로 본 시스템의 대상이 아니다. 반면 **이론평가**는 전국 **19개 소방본부**가 각자 다른 방식(구글 폼, 종이시험, 자체 플랫폼 등)으로 운영하고 있어, **평가 방식의 불통일, 신뢰성 저하, 행정 비효율** 문제가 지속되고 있다.

서울소방재난본부는 2026년 3월, 자체 개발한 웹 기반 CBT(Computer Based Test) 시스템을 통해 **26개 소방서, 약 5,300명을 대상으로 전 소방서 동시 이론평가**를 실시하였으며, 기존 방식(결과 취합·오류 재처리·통계 정리까지 약 3일 소요) 대비 **시험 종료 즉시 자동 완료, 수동 재채점 요청 0건**이라는 유의미한 성과를 거두었다. 또한 응시자 측면에서도 스마트폰·PC를 통한 디지털 방식으로 시험에 응시할 수 있어 접근성이 크게 향상되었으며, 시험 종료 후 **오답 문항을 즉시 확인**할 수 있어 자기주도 학습에 도움이 되었다는 긍정적인 반응이 다수 있었다.

이에 본 시스템을 전국 소방본부에 확산하고, 나아가 소방청 주도의 전국 표준 이론평가 플랫폼으로 발전시키고자 본 제안서를 제출한다.

## 3. 서울소방재난본부 기존 방식(구글 폼)의 문제점

서울소방재난본부는 기출문제를 사전 공개하고, QR코드를 통해 구글 폼에 접속하면 기출문제 중 20문제가 무작위로 출제되는 방식으로 운영하였다.

### 3-1. 직종별 QR코드 다중 관리 문제

평가 문항의 범위가 직종(진압대·구급대·구조대·지휘대·기동대)에 따라 달라, 직종별로 별도의 구글 폼과 QR코드를 제작·관리해야 했다.

일선 소방서(센터)의 경우 한 근무조에 진압대 4~5명, 기동대원 2명, 구급대 3명 등 여러 직종이 혼재하여, 평가 진행 시 **최소 3개의 QR코드**를 준비·배포해야 했다. 본서 직할 부대(대응단 등)는 지휘팀·구조대 등이 추가되어 QR코드 수가 더 늘어났다.

| 문제 | 내용 |
|------|------|
| QR코드 다중 관리 | 직종 수만큼 폼·QR 제작 및 버전 관리 필요 |
| 배포 혼선 | 현장에서 직종별 QR코드 구분·배포 과정에서 오배포 가능성 |
| 수정 시 재작업 | 문항 변경 시 해당 직종 폼 전체를 다시 제작 |
| 데이터 분산 | 직종별로 결과가 분리 저장되어 통합 집계 별도 작업 필요 |

### 3-2. 채점 오류 빈발 및 구조적 한계

구글 폼은 정답이 하나로 고정된 단순 객관식 채점만 지원한다. 복수 정답·부분 점수·조건부 채점 등 유연한 채점 방식을 적용할 수 없어, 문항 설계 자체가 제한될 수밖에 없다.

더 큰 문제는 **문제 오류 발견 시 일괄 수정이 불가능**하다는 점이다. 구글 폼은 제출된 응답 데이터와 채점 결과가 연동되어 있어, 문항 하나를 수정하면 이미 제출된 전체 응시 데이터에 대해 수동으로 재채점해야 한다. 실제로 구급대원 평가에서 문제 오류가 발견되어 **약 2,000명 분의 데이터를 수작업으로 재처리하는 데 약 3시간이 소요**된 사례가 발생하였다.

또한 구글 폼은 **문제은행(Question Bank) 기능을 제공하지 않는다.** 전 세계 교육 현장에서도 지적되는 구글 폼의 대표적 한계로, 문항을 누적·분류하여 관리하거나 시험마다 자동으로 다른 문제를 조합하는 기능이 기본 제공되지 않는다. 서울소방재난본부는 별도 스크립트를 적용해 무작위 출제를 구현하였으나, 이는 공식 기능이 아닌 우회적 방법으로 안정성 및 유지보수에 한계가 있다.

### 3-3. 데이터 분산으로 인한 통계 관리 어려움

직렬별로 구글 폼이 분리되어 있어, 결과 데이터도 **직렬 수(6개)만큼 별도 스프레드시트**로 나뉘어 저장된다. QR코드는 직렬별 6개로 운영하면 되지만, 시험 종료 후 소방서별·직렬별·부서별 통계를 만들려면 6개 시트를 수동으로 취합·교차 정리해야 한다.

- 응시 이력, 점수 추이, 소방서별·직렬별 현황 등 **원하는 기준으로 통계를 바로 조회하는 기능 없음**
- 전체 현황을 보려면 6개 시트에서 데이터를 복사·붙여넣기하거나 VLOOKUP 등으로 수동 가공 필요
- 특정 소방서나 부서의 응시 결과를 뽑으려면 6개 시트를 각각 필터링해야 하는 반복 작업 발생
- 데이터가 구글 서버에 분산 저장되어 **장기 이력 관리 및 반기별 비교 분석 불가**

### 3-4. 공정성 및 본인 확인 문제

본 시스템의 문제은행은 총 **약 400문제**로 구성된 공개된 기출문제 풀로 운영되며, 매 시험마다 무작위 출제된다. 구글 폼으로도 무작위 출제는 구현 가능하나, 아래와 같은 구조적 취약점이 존재한다. 이는 소방에만 국한된 문제가 아니라 **구글 폼을 시험 도구로 사용하는 모든 기관에서 공통적으로 제기되는 한계**이다.

- **시간 제한 미작동**: 기본 구글 폼에는 시간 제한 기능이 없어, 응시자가 충분한 시간을 들여 검색·참고 후 답변 가능
- **탭 전환 감지 불가**: 시험 중 다른 브라우저 탭이나 앱으로 전환해도 이를 감지하거나 기록할 수 없음
- **응시 횟수 제한 없음**: QR코드나 링크를 아는 사람이라면 횟수 제한 없이 반복 응시 가능
- **본인 확인 불가**: 계정 인증 없이 이름을 직접 입력하는 방식이므로, 타인 명의로 응시하거나 대리 응시해도 확인할 방법이 없음
- **링크 공유 차단 불가**: QR코드나 링크가 외부로 유출되면 응시 대상이 아닌 인원도 접근 가능
- **실시간 감독 불가**: 응시 현황이 관리자에게 실시간으로 집계되지 않아 이상 응시를 즉시 파악하기 어려움

CBT 시스템은 계정 로그인 기반으로 운영되어 **본인 인증, 응시 횟수 제한(1일 최대 2회), 20분 시간 제한, 실시간 응시 현황 모니터링**이 자동 적용된다.

### 3-5. 전국 평가 방식 불통일

- 전국 19개 소방본부가 **각기 다른 평가 도구·방식**을 사용
- 평가 결과의 비교·분석 불가
- 소방청 차원의 전국 훈련 현황 파악 불가

## 4. 시스템 개요 및 주요 기능

### 4-1. 접속 방법

- 별도 앱 설치 없이 **웹 브라우저**로 접속 (PC·스마트폰 모두 가능)
- 로그인 후 본인 직렬 선택 → 즉시 시험 시작

### 4-2. 주요 기능

| 구분 | 기능 |
|------|------|
| 응시자 | 직렬별 맞춤 문제 출제, 20분 제한, 자동 채점, 즉시 결과 확인 |
| 재응시 | 하루 최대 **2회** 응시 가능 (출동·기타 상황 발생 시 1회 추가 기회 부여) |
| 문제 관리 | 직렬별 문제은행, 무작위 출제, 문제 추가·수정·삭제 |
| 관리자 | 응시 현황 실시간 조회, 소방서·부서·직렬별 통계, 엑셀 내보내기 |
| 공지사항 | 관리자 공지 등록·수정·삭제 (응시자 메인 화면 노출) |
| 보안 | 계정 기반 접근 제어, Firestore 보안 규칙 적용 |

> ※ 재응시 2회 제한: 출동, 비상근무 등 불가피한 상황으로 시험을 완료하지 못한 대원에게 당일 1회 추가 응시 기회를 부여하되, 무분별한 재응시는 제한

### 4-3. 직렬별 출제 구성

| 직렬 | 출제 과목 및 문항 수 |
|------|-------------------|
| 지휘대 | 안전관리 10 + 소방시설 10 |
| 진압대원 | 화재 10 + 소방시설 5 + 안전관리 5 |
| 구조대원 | 구조 10 + 소방시설 5 + 안전관리 5 |
| 구급대원(자격자) | 구급 15 + 안전관리 5 |
| 구급대원(교육이수자) | 구급 15 + 안전관리 5 |
| 기동대원 | 장비 10 + 안전관리 10 |

| 문제 오류 수정에 개발 지식 필요 | 관리자 화면에서 문항 수정 기능 미구현 — 소스코드 및 개발 환경을 보유한 개발자만 수정 가능 | 향후 개선이 필요한 사항으로 인식 중 |

## 6. 소방청 연계 및 공식화 방안

### 6-1. 현황

현재 본 시스템은 서울소방재난본부 내부적으로 개발·운영 중이며,  
소방청 공식 승인 또는 등록된 사이트가 아닌 상태이다.

### 6-2. 개인정보 및 보안 검토

본 시스템은 Google Firebase(서울 리전, asia-northeast3)를 기반으로 운영되며, 데이터는 **국내 서버에 저장**된다. 다만 공공기관 정보보호 지침 적용 여부에 따라 아래 단계적 대응이 필요하다.

| 단계 | 내용 |
|------|------|
| 단기 | 개인정보 처리방침 수립 및 고지, 최소 수집 원칙 적용 |

| 장기 | 필요 시 행정안전부 G-Cloud(공공 클라우드)로 전환 |

> ※ 현재 수집 정보: 이름, 소속(소방서·부서), 직렬, 시험 점수, 이메일 주소에 한정되며, 주민등록번호 등 민감정보는 수집하지 않음

### 6-3. 지속 운영 및 책임 체계

### 6-4. 전국 확산을 위한 소방청 협조 요청 사항

본 시스템의 전국 활용을 위해 소방청의 아래 사항에 대한 협조를 요청한다.

소방청은 본 시스템을 전국 표준 플랫폼으로 활용하기 위한 전제 조건으로 **서울시 차원의 공식 승인**을 요구하고 있다. 서울시 공식 승인이 이루어져야 소방청이 본 시스템을 공식 채택·배포하는 데 필요한 행정적 근거가 마련되기 때문이다.

1. **서울시·서울소방재난본부 공식 승인**  
   - 서울시 및 서울소방재난본부 차원의 정식 도입 결재 및 공문 발행  
   - 서울소방 공식 사이트 또는 인트라넷에 링크 등록  
   - 소방청의 전국 확산을 위한 선결 조건  

2. **소방청 직장훈련 플랫폼 목록 등재**  
   - 소방청 직장훈련 지침 내 공식 평가 도구로 명시  
   - 전국 소방본부 도입 시 소방청 승인 플랫폼으로 활용 가능하도록 근거 마련  

3. **보안 심의 및 개인정보 검토 협조**  
   - 소방청 정보보안 담당 부서의 시스템 보안 심의 진행  
   - 개인정보 처리방침 적정성 검토 지원

## 7. 전국 확산 계획

### 7-1. 확산 방식 (2가지 안)

**[1안] 서울 시스템 공동 활용**  
- 서울이 운영 중인 시스템에 각 소방본부 계정 추가  
- 별도 구축 비용 없음, 빠른 도입 가능  
- 단, 문제은행은 소방본부별로 분리 관리 필요  

**[2안] 소방청 주관 전국 단일 플랫폼 구축** *(권장)*  
- 소방청이 주관하여 전국 통합 시스템 구축  
- 소방본부별 관리자 계정, 문제은행, 통계 독립 운영  
- 소방청은 전국 현황 통합 조회 가능  
- 표준 문제은행 제공으로 출제 공정성 확보  

### 7-2. 도입 단계

```
1단계 (2026 하반기)  서울 + 수도권 소방본부 시범 적용
                     경기남부, 경기북부, 인천 우선 적용

2단계 (2027 상반기)  전국 19개 소방본부 확산
                     소방청 공식 플랫폼 등재

3단계 (2027 하반기)  문제은행 전국 표준화
                     소방청 직장훈련 지침 개정 반영
```

### 7-3. 소방본부별 커스터마이징 가능 항목

- 소방서·부서 조직도 (현재 서울 조직 기준 → 각 소방본부별 변경 가능)
- 직렬별 출제 문항 수 및 과목 구성
- 문제은행 (각 소방본부 자체 문제 추가·수정)
- 관리자 계정 및 권한 체계

## 8. 소요 예산

### 8-1. 현재 운영 비용 (서울, 연간)

| 항목 | 비용 | 비고 |
|------|------|------|
| Firebase Hosting | 무료 | 현재 무료 플랜 |
| Firestore DB | 무료 | 5,300명 응시 시 읽기 한도를 4회 초과했으나 응시·데이터 조회 모두 정상 작동 — Firebase가 초과 즉시 차단하지 않음 |
| 도메인 | 무료 (web.app 기본 도메인) | 공식 도메인 필요 시 별도 |
| **소계** | **실질적 0원** | 현재 기준 |

> ※ Firestore 읽기 한도 초과는 관리자가 결과 엑셀 내보내기 시 발생. 시험 종료 후 조회 횟수를 최소화하면 무료 플랜으로도 운영 가능  
> ※ 응시 인원이 지속적으로 늘거나 수시 조회가 필요한 경우 Blaze(종량제) 전환 시 월 수만원 수준으로 해결 가능

### 8-2. 전국 확산 시 예산 (추정)

**운영 인프라 비용 (소방본부별 독립 운영)**

전국 확산 시 각 소방본부가 **Firebase 프로젝트를 독립적으로 구축·운영**하는 방식을 채택한다.  
(예: 서울 별도, 경기남부 별도, 경기북부 별도, 인천 별도 등)

이 방식은 소방본부별 데이터 분리·보안이 보장되며, Firebase 무료 플랜(Spark) 기준으로  
**각 소방본부별 응시 인원이 일정 규모 이하라면 추가 서버 비용 없이 운영 가능**하다.

본 시스템은 이미 완성된 형태로, 각 소방본부가 **Firebase 프로젝트만 생성하면 별도 개발 비용 없이 즉시 도입 가능**하다. 소스코드 및 설치 가이드는 인수인계 문서와 함께 제공되며, 소방본부 내 담당자가 직접 운영·관리할 수 있는 구조이다. 문제은행 역시 서울 운영 중인 약 400문제를 기반으로 소방본부별로 자체 추가·수정하면 되므로 별도 구축 비용이 발생하지 않는다.

| 항목 | 금액 | 비고 |
|------|------|------|
| 서버 인프라 | **무료~소액** | 소방본부별 Firebase 독립 운영 (Spark 무료 플랜 기준) |
| 운영·유지보수 | **자체 담당** | 별도 외주 없이 소방본부 내 담당자 운영 가능 |
| **합계** | **실질적 0원** | 추가 예산 없이 전국 확산 가능 |

> ※ 응시 인원이 많아 Firebase 무료 한도를 초과하는 소방본부의 경우, Blaze(종량제) 전환 시 월 수만원 수준의 비용이 발생할 수 있으나 이는 각 소방본부 자체 예산으로 처리 가능한 수준  
> ※ 구글 폼 기반 수기 채점 인력 대비 **행정비용 절감 효과가 도입비용을 크게 상회**

## 9. 기대 효과

### 9-1. 행정 효율화

- 결과 취합·오류 재처리·통계 정리 등 전 과정 자동화로 반복 행정 작업 **완전 제거**
- 5,300명 기준 결과 처리 전 과정 **약 3일 → 즉시** 완료
- 오류 발생 시 즉시 일괄 수정 (기존: 문제 오류 1건에 약 2,000명 수동 재처리 필요)
- 결과 통계 실시간 조회 및 엑셀 자동 내보내기

### 9-2. 평가 신뢰성 향상

- 계정 기반 본인 확인으로 **대리 응시·부정행위 방지**
- 시간 제한(20분) 및 응시 횟수 제한(1일 최대 2회) 자동 관리
- 채점 오류 **0%** (기존 방식 대비 오류 완전 제거)

### 9-3. 소방공무원 현장 역량 향상

- 시험 종료 후 **오답 문항 즉시 확인** 가능 → 자기주도 학습 지원
- "내가 어느 부분이 부족한지 바로 알 수 있어 공부에 도움이 됐다"는 응시자 후기 다수
- PC·스마트폰 어디서나 응시 가능한 디지털 환경으로 응시 편의성 향상

### 9-4. 전국 표준화

- 전국 19개 소방본부의 **평가 방식 통일** (현재: 소방본부별 상이)
- 소방청 주도의 표준 문제은행 운영 가능
- 소방본부별 성과 비교·분석 → 훈련 취약 분야 파악
- 소방청 연간 직장훈련 성과 보고 데이터로 활용 가능

### 9-5. 비용 절감

| 구분 | 기존(구글 폼) | CBT 시스템 |
|------|------------|-----------|
| QR코드 관리 | 직종별 다수 제작·배포 | 로그인 1회로 대체 |
| 결과 처리 전 과정 | 취합·재처리·통계 정리 약 3일 소요 | 시험 종료 즉시 자동 완료 |
